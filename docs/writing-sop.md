## 一、5阶段工作流程

### Phase 1 — 选题审查（必须执行，禁止跳过）
- [ ] 检查选题池映射表，确认不与已发布文章大面积重叠
- [ ] 如选题为已发文章的"进阶版"（如T3是#04的进阶），须明确区分角度
- [ ] 确认选题在Tier 1优先（高共鸣+高实用），除非主人另有指定
- [ ] 检查 `.topic-pool.md` 和 `topic-pool-nihaixia.md` 知识储备

### Phase 2 — 漫画脚本（先于正文）
- [ ] 写4格漫画脚本（Ollie猫头鹰IP贯穿）
- [ ] 风格：2D扁平手绘，朱砂红头#b83a2a、杏色腹#e8a87c、金阴阳吊坠
- [ ] 拒绝"可爱"风格，保持温暖智慧
- [ ] 漫画脚本文件：`docs/comic-scripts/article-XX-script.md`
- [ ] 漫画生成后保存为 `images/comic-XX-title-new.png`

### Phase 3 — 正文起草
- [ ] 开篇：个人体验/生活场景切入（窦文涛式"不装"）
- [ ] 主体：1个核心概念 + 2-3个具象类比 → 1-2个实用建议
- [ ] 结尾：金句收尾，"放下"而非"记住"
- [ ] 遵循 Ollie 表达方法论（见 `.topic-pool.md` 第四节）
- [ ] 禁止词：essays/academic/scholarly/comprehensive/treatise/lecture

### Phase 4 — 8维自评
- [ ] 逐项打分（见下方评分表）
- [ ] 总分≥9.0 → 通过；<9.0 → 回到Phase 3重写
- [ ] 评分记录写入当日工作日志

### Phase 5 — HTML发布
- [ ] 创建 `posts/XX-slug.html`
- [ ] 更新 `index.html` 文章列表
- [ ] 确保 og:image 指向漫画图片
- [ ] 包含百度统计代码
- [ ] FAQ结构化数据（JSON-LD）

## 二、8维评分标准（阈值9.0）

| 维度 | 权重 | 评分标准 | 满分描述 |
|------|:---:|---------|---------|
| 1. 内容准确性 | 20% | TCM概念无硬伤，引用经典有据 | 经得起中医专业读者审视 |
| 2. 英文流畅度 | 20% | 母语级自然表达，无翻译腔 | 英语读者不会觉得"这是翻译的" |
| 3. 可读性/趣味性 | 15% | Ollie语气贯穿，类比生动 | 读完全文不费力，想分享 |
| 4. 西方读者适配 | 15% | 类比来自西方生活经验，术语极少 | 不需要中国文化背景就能懂 |
| 5. SEO友好度 | 10% | 标题含搜索意图关键词，meta完整 | 标题能独立引流 |
| 6. 结构逻辑 | 10% | 开篇→展开→收尾，过渡自然 | 读完有"完整感" |
| 7. 差异化/独特价值 | 5% | 不与已有文章重复，有独特角度 | 读者觉得"这个角度没听过" |
| 8. 漫画匹配度 | 5% | 漫画准确传达核心概念，风格一致 | 图文互相增强 |

**计算公式**：总分 = Σ(维度得分 × 权重)

**自评要求**：每写完正文必须逐项打分，低于9.0必须重写。评分记录写入工作日志。

## 三、铁律（永久生效）

1. **漫画先行**：先定漫画脚本再写正文，确保文章有视觉锚点
2. **Ollie IP贯穿**：每篇文章Ollie必须出场（至少漫画中）
3. **漫画原图禁止处理**：AI生成的漫画PNG直接使用，不做二次编辑
4. **反可爱**：Ollie是智慧温暖的猫头鹰，不是cute mascot
5. **懒兔子风格**：轻松幽默接地气，不端着不贩卖焦虑
6. **自评<9分必须重写**
7. **发布前主人审阅**：HTML完成后先给主人预览，批准后推送
8. **发布后写工作日志**：记录选题、评分、经验教训
